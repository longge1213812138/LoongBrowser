# ADR-0008：启动页与「＋新标签」分开

- 状态：已采纳
- 日期：2026-10-19

## 背景

浏览器启动时显示空白页。用户要求"增加自定义浏览器打开时显示指定网站功能"，同时明确"点击新标签功能按钮时依旧要显示书签墙"。

这两句话合起来是一条边界：**启动页和新标签页是两个入口，不能合并**。

## 决策

1. 新增 `StartupPageSettings`，三选一：`blank`（默认）/ `wall` / `url`，落盘 `startup.json`。
2. 启动窗口按设置打开；工具栏「＋新标签」**始终** `NewTab(null)`，不读设置。
3. 默认值保持 `blank` —— 加功能不改既有行为，想要什么由用户显式选。
4. 命令行带了地址（双击 `.html`、外部打开）时优先于设置。

## 为什么默认不是书签墙

一度把默认改成"启动即书签墙"（看起来更"有用"），但那是在**擅自改变既有行为**：用户提的是"增加能力"，不是"换掉现在的样子"。默认值该是当前行为，新选项让用户主动选。

## 为什么两个入口要能分辨

两者渲染同一张墙，但页头与标签页标题不同：
- 「＋新标签」→ 页头「书签」，标签页「新标签页」（沿用旧值，用户已经认得）
- 启动即书签墙 → 页头与标签页都是「启动页」

如果两者完全同名，用户从任务栏/标签条看不出当前是启动页还是新开的新标签页，也就无从判断设置有没有生效。为此 `TabInfo.WallTitle` 记住每张墙自己的标题，`RefreshNewTabPages` 按原标题重渲染 —— 否则书签一增删，启动页就被刷成「书签」。

## 代价

- 多一个数据文件（`startup.json`）；损坏或缺失一律回落空白页，不弹错。
- `NewTab` 多一个 `wallTitle` 参数；不传等价于旧行为。
- 两个入口共用 `BuildHtml`，标题只影响 `<title>` 与页头，卡片区逐字节一致（测试 D4 断言）。
